This page is part of the **sample 2** product view in the CodeWeTrust dashboard. It allows staff to review technical debt issues detected in the codebase, configure how much of each issue type should be fixed, and see the calculated effort (in hours/days) required to resolve them.

## Technical Debt Table

This table lists each category of detected technical debt issue and lets the user configure fix targets and effort per issue.

**Columns:**

- **Issue (row label, clickable link):** Name of the issue category (e.g., Bugs, Code Smells, Vulnerabilities). Clicking the link likely navigates to a detailed list of that issue type.
- **Total number of Issues:** Shows how many issues of that type were detected in the codebase.
- **Min Severity (dropdown):** Lets the user select the minimum severity level (e.g., Critical, Blocker) to include when calculating debt for that issue type.
- **Percentage To Fix (slider with green marker and % label):** Lets the user drag the slider to set what percentage of the detected issues should be considered "to fix." The percentage value is displayed below the slider (e.g., 0%, 12%, 50%, 100%).
- **Effort (hours) (editable numeric field):** Shows/allows editing of the estimated hours required to fix one instance of this issue type.
- **Issues Under Consideration ("x N"):** Shows the number of issues actually being counted based on the percentage-to-fix setting.
- **Hours of Required Effort ("= N"):** Shows the calculated total hours needed for this issue type (Effort × Issues Under Consideration).
- **Toggle switch (rightmost column):** Enables or disables inclusion of that issue category in the overall technical debt calculation. When toggled off, the row's values would not count toward the totals.

**Rows (Issue Categories):**

- **Bugs**
- **Code Smells**
- **Vulnerabilities**
- **Code Risks**
- **Duplicate Code**
- **Security Hotspots**
- **Outdated 3rd Party Packages**
- **Risky Licenses**

Each row follows the same interactive pattern described above, letting the user tailor severity thresholds, fix percentages, and effort estimates independently per issue type.
